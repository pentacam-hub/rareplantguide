# Cloudflare Content + Pinterest Agent — GitHub Actions replacement

This replaces all scheduled Rare Plant GitHub Actions jobs with Cloudflare.

## Architecture

1. `rareplant-content-scheduler` is a tiny Cloudflare Worker with three Cron Triggers.
2. It calls one of two secret Deploy Hooks on a dedicated Cloudflare Pages agent project.
3. The agent project uses marker branches only to select the job type, then immediately fetches and runs the latest automation code from `main`.
4. Content mode runs the existing Python article generator, creates the cover + vertical Pin creative, commits source files to `main`, waits for the production site, and posts one original Pin.
5. Promo mode prepares and posts one evergreen Pin from existing content and commits its queue state.
6. The production Rare Plant Pages project builds only source changes from `main`; `public/` is no longer generated by scheduled GitHub Actions.

## Schedules (UTC)

- `30 14 * * *` → evergreen promo every day at 14:30 UTC
- `30 19 * * 0,2,3,5,6` → second evergreen promo Sun/Tue/Wed/Fri/Sat at 19:30 UTC
- `30 19 * * 1,4` → new article + original Pin Monday/Thursday at 19:30 UTC

These are already stored in `cloudflare/content-scheduler/wrangler.jsonc`.

## A. Production Pages project

Use the existing Rare Plant Pages project.

- Production branch: `main`
- Build command: `bash scripts/cloudflare-build.sh`
- Build output directory: `public`
- Environment variable: `HUGO_VERSION=0.148.2`
- Automatic production deployments: ON
- Settings > Build > Build watch paths > Exclude: `content-queue.yaml`

The queue-only status commit after Pinterest publishing should therefore not cause a redundant production build.

## B. Dedicated agent runner Pages project

Create one additional Pages project connected to `pentacam-hub/rareplantguide`.

Suggested project name: `rareplant-content-agent`

Use:

- Build command: `bash scripts/cloudflare-agent-entry.sh`
- Build output directory: `.agent-output`
- Automatic production deployments: OFF
- Automatic preview deployments: OFF
- Recommended variable: `PYTHON_VERSION=3.11`

Add these build secrets:

Required:
- `GEMINI_API_KEY`
- `PINTEREST_APP_ID`
- `PINTEREST_APP_SECRET`
- `GITHUB_CONTENT_TOKEN`

Optional:
- `UNSPLASH_ACCESS_KEY`
- `PINTEREST_REFRESH_TOKEN` (fallback only; client credentials are preferred)

`GITHUB_CONTENT_TOKEN` must be a fine-grained GitHub token restricted to `pentacam-hub/rareplantguide` with **Contents: Read and write**. Never store it in source control.

### Marker branches

Two stable branches are used only so Deploy Hooks can select the mode:

- `cf-agent-content`
- `cf-agent-promo`

`scripts/cloudflare-agent-entry.sh` reads `CF_PAGES_BRANCH`, fetches the latest `main`, checks out that current code, then runs the correct agent script. The marker branches therefore do not need to be kept synchronized manually.

### Deploy Hooks

Create two hooks in the agent Pages project:

1. Name: `scheduled-content-agent`
   - Branch: `cf-agent-content`

2. Name: `scheduled-promo-agent`
   - Branch: `cf-agent-promo`

Copy both URLs and treat them as secrets.

## C. Scheduler Worker

Create/deploy the Worker from:

`cloudflare/content-scheduler`

The checked-in Worker has `/health` plus protected manual endpoints and the three Cron schedules above.

Add Worker secrets:

- `CONTENT_AGENT_DEPLOY_HOOK_URL` = content hook URL
- `PROMO_AGENT_DEPLOY_HOOK_URL` = evergreen promo hook URL
- `MANUAL_TRIGGER_TOKEN` = optional long random token

Endpoints:

- `GET /health`
- `POST /run/content`
- `POST /run/promo`

When `MANUAL_TRIGGER_TOKEN` is configured, manual POST requests require:

`Authorization: Bearer <token>`

## D. GitHub Actions state

The following workflows are now manual fallbacks only and must contain no `schedule`, `push`, or `pull_request` trigger:

- `.github/workflows/build-site.yml`
- `.github/workflows/auto-post.yml`
- `.github/workflows/pinterest-promo.yml`
- `.github/workflows/pinterest-ci.yml`

Analyze My Income Pinterest workflows in this repository are also already manual-only.

## E. Safe cutover test

1. Create the two marker branches if they do not exist.
2. Create the dedicated agent Pages project and add the secrets above.
3. Create the two Deploy Hooks.
4. Deploy the scheduler Worker and add its hook secrets.
5. Trigger `scheduled-content-agent` manually once.
6. Confirm the agent build creates a source commit on `main` without changing `public/`.
7. Confirm the production Pages project builds the source commit.
8. Confirm article + Pin image are HTTP 200 and one original Pinterest Pin is posted (or an existing Pin is recognized).
9. Trigger `scheduled-promo-agent` manually once and confirm one evergreen Pin is processed.
10. Confirm the Pinterest status-only commit does not trigger a production Pages build.
11. Confirm no automatic GitHub Actions run is created.
